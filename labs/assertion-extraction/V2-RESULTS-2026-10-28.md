# Contextual parser v2: results and remaining work

This update improves the parser's usefulness, particularly nearby references, explicit
versions, and the reviewed wrong attribute assignments. It remains a partial extractor;
most practice assertions are still not recovered. It does not decide truth or implement
the competition solver. The [plan](IMPROVEMENT-PLAN-2026-10-28.md) describes the broader
direction; statistical tagging/ranking and independent end-to-end evaluation remain future work.

## Implementation and comparison

The runtime uses deterministic NLP: lexicon mention recognition, predicate/role patterns,
protected date spans, version recognition, qualifier capture and bounded discourse
resolution. It is safe Rust, one thread, with no model downloads, external service,
LLM/SLM, training dependencies or new Cargo dependencies. This is a rule-based language
parser, not a pretrained dependency parser or trained statistical model.

The context ablation adds 146 matching pairs on this development dataset. Matching a
pair does not prove that the wording, condition, version scope or whole-row coverage
is correct. Forms sometimes omit linguistically supported assertions. These numbers
are not a clean generalization estimate: reviewed practice cases informed the rules.
There are still 44 rows marked `split` whose pair multisets differ from the forms.
`split` continues to mean all emitted fragments are paired, not verified completeness.

Manual inspection during development caught false context inheritance from Max to
unrecognized “Lite”/“Plus” subjects (`p-925`/`p-926`) and from Workspace to “AI Pro”
(`p-862`). Those cases now abstain, including coordinated predicates belonging to an
unrecognized named actor. This loses recall but avoids putting values under the wrong
product. A later reviewed shorthand/plan resolver should recover them explicitly.

Remaining weaknesses include incomplete shorthand and predicate coverage, uncertain
same-date document boundaries, unresolved relative clauses, and incomplete clause
inventories. The normalizer is still conservative; role compatibility is hand-written,
not a full dependency grammar. Scope records preserve wording rather than interpreting
effective dates, cumulative counts or conditions. A lexicon-compatible pair can still
be incomplete or wrong. Do not use these records as automatically trusted KB facts.

## Reproducibility and validation

Use the lab README commands to compile a schema-v2 index and regenerate the two practice
CSVs. Add `--context off` for the ablation. The viewer uses the same output and shows
antecedent navigation and qualifier records. Core/CLI tests cover staged parity, label/
form independence, date boundaries, ambiguous people, context expiry, foreign actors,
version scope, original byte spans, date attachment and bounded long-row abstention.

The implementation handoff records final check and resource results. No official
checker pass or full-solver accuracy is claimed. Development-authored rules and test
fixtures used Codex assistance; synthetic facts are never Hooly evidence.


Parser-only resource checks: 20,000 repeated practice rows completed in 4.03 seconds
with 41,084 KiB child-process peak RSS on a Ryzen 7 6800HS, one parser thread and
CPU affinity limited to two cores. An offline UID-10001 read-only container with two
CPUs/6 GiB completed the same input in 4.67 seconds including startup and produced
identical output. Its runtime image was 79,509,337 bytes. The local Docker builder lacks
BuildKit, so the smoke build used a temporary Dockerfile with only build-cache mounts
removed; the root Dockerfile was not modified. This does not certify the full solver.
