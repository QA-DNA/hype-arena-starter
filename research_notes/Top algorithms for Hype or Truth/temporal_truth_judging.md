# Temporal truth judging / verification: ranked algorithms for Hooly "Hype or Truth"

Caveats up front
- The instruction file researcher.md was not found at the given path, and I did no live web verification. Citations are from memory (venue/year given); verify titles before citing in a write-up. Accuracy gains marked (est.) are my arithmetic from your measured buckets, not measured results.
- Everything here assumes your numbers: gold-facts judge 92.0% / ll 0.222, parser-facts judge 87% / ll 0.35. The gap (about 5 points, 0.13 ll) is the biggest single recoverable loss, larger than anything a better timeline model can add on gold facts. Rank reflects that.

## Where the errors are (budget)
Per 1,858 rows: gold-fact judge errs ~8% = ~150 rows. The "one side known and differs" bucket (174 true / 114 false = 288 facts) is the dominant irreducible-looking chunk: a flat 60/40 guess errs ~40% of it, about 115 facts. A model that gets that bucket to 70% saves ~30 facts = ~1.5 points acc. Parser loss costs ~5 points. Unlabelled-row densification (10x rows) could shrink both the "no observation" and "one side" buckets. So: fix parser-uncertainty first, densify second, sharpen the uncertain bucket third.

## Rank 1: Soft parse marginalisation + attribute-free value matching
What: Instead of hard (subject, attribute, value), keep K hypotheses h with posterior pi_h(x) and compute P(true|x) = sum_h pi_h(x) * P(true|evidence_h), with a "no-parse / default" hypothesis carrying the prior (~0.85) mass. Attribute-free matching: for a detected subject and a detected value (number+unit, name, date), look the value up across ALL of that subject's attribute timelines (and, if subject uncertain, all subjects with that alias), and score compatibility per attribute; the attribute posterior comes from a small classifier on words around the value.
Primary sources: latent-variable / mixture-of-experts training by EM (Dempster, Laird, Rubin 1977, JRSS-B); "expected features" is the standard trick for latent structure in discriminative models (Quattoni et al., "Hidden conditional random fields", TPAMI 2007; Yu & Joachims latent SVM, ICML 2009). Marginalising over semantic-parse hypotheses: Zettlemoyer & Collins 2005/2007 (log-linear PCCG with latent derivations).
Why it fits: 252 of 502 gold facts change over time, and parser recall 0.69 / precision 0.91 means ~31% of facts yield no evidence and fall into the "no observation, 98.8% true" default, which is only right because 85% of rows are true; false rows with unparsed facts are lost. The lexicon (62 subjects, 514 subject-attribute pairs) is a tiny closed world: value lookup is a cheap hash join.
Needs: gold `form` on 1,897 practice rows (training for hypothesis posterior); lexicon; your existing timeline builder.
Runtime: negligible (K<=5 hypotheses x timeline lookup; 20k rows in seconds).
Expected gain: recovers part of the 5-point gap. Realistic +1.5 to +3 acc, ll -0.04 to -0.08 (est.). The gold-vs-parser gap is the ceiling.
Recipe:
1. For each row, enumerate candidate (subject, value) pairs by alias+number extraction with recall-biased rules (emit every number/money/percent/date/name candidate, not just those the attribute rules accept).
2. Attribute posterior: multinomial logistic regression (sklearn) over hashed n-grams in a +-6-token window around the value, restricted to attributes valid for the subject (lexicon). Train on gold forms from practice (each gold fact = one training example; value span located by string match). Calibrate (see rank 4).
3. For each (subject, attr, value) hypothesis compute the bracketing features you already have. Also compute attribute-free features: best compat over ALL attributes of the subject (max, and posterior-weighted mean), "value equals some value seen for this subject on any attribute" flag.
4. Two ways to combine; pick the cheaper first:
   a. Feature route (1 hour): feed GBM the top-2 hypotheses' feature blocks sorted by posterior, plus the posterior values, plus the marginalised scalar P = sum pi_h * p_h from the existing GBM. Train/CV as now.
   b. EM route (3 hours): p(y=true|x) = sum_h pi_h(x) * sigmoid(w.phi_h) with h latent; E-step: responsibilities r_h proportional to pi_h * sigmoid(w.phi_h)^y * (1-sigmoid)^(1-y); M-step: weighted logistic regression with each (row, h) a weighted sample. Converges in ~10 iterations; no library needed beyond sklearn's sample_weight.
5. Use gold-form rows to measure it: train with hard gold vs. soft parse, report the closed fraction of the 5-point gap.
Pitfalls: pi_h must be calibrated or marginalisation over-trusts wrong attributes; an attribute-free match will match coincidental numbers (round values like 100, years); restrict by unit/kind (money vs headcount vs percent) and weight by value rarity (idf of the value within the subject). A false row where the lie replaces a value with another real value of a different attribute would then look true; check against the 158 "invented" facts.

## Rank 2: Transductive timeline densification (unlabelled universe as soft observations), via EM / truth discovery
What: Treat every parsed fact in all ~20k rows as a noisy observation of the subject-attribute timeline, weighted by the current estimated P(true) of its row; recompute timelines, re-judge, iterate (self-training with soft labels). This is truth discovery where the "sources" are rows/doc-types and truth is a step function of time.
Primary sources: Yin, Han, Yu, TruthFinder, KDD 2007 / TKDE 2008; Dawid & Skene 1979 (JRSS-C); Zhao et al., "A Bayesian Approach to Discovering Truth from Conflicting Sources" (LTM), VLDB 2012; Li et al., CRH, SIGMOD 2014; Li et al., "A Survey on Truth Discovery", SIGKDD Explorations 2015; Dong, Berti-Equille, Srivastava, "Truth Discovery and Copying Detection in a Dynamic World", VLDB 2009 (temporal lifespan + copying) and Pal et al., "Information Integration over Time in Unreliable and Uncertain Environments", WWW 2012 (dynamic truth discovery with evolving truth). Self-training: Yarowsky 1995; calibration-aware: Wei et al. 2021 (self-training theory); Snorkel data programming: Ratner et al., NeurIPS 2016 / VLDB 2017.
Why it fits: at test time the only gold observations are the 1.9k practice labels across a 20k-row universe, so most subject-attribute timelines are sparse. If 85% of unlabelled rows are true, a parsed value stated in an unlabelled row is a true observation with ~0.85 prior, and corroboration by several rows near the same date pushes it much higher. This directly attacks the "no observation" and "one side known" buckets.
Needs: parser run over all rows (offline, once; fast); your judge as the E-step.
Runtime: each round = parse once, rebuild timelines (hash/sort by (subject, attr)), GBM predict on 20k rows: seconds to a minute. 3 rounds fine within 30 min.
Expected gain: uncertain; your Judge B (all rows as time-decayed votes) got 0.908 vs bracketing A 0.920 on practice-only, i.e. votes alone are weaker than labelled brackets, but the practice universe is 10x smaller than the test universe. Plausible +1 to +3 acc on test (est.), and the largest risk of a train/test mismatch in the whole project.
Recipe:
1. Pass 0: judge A trained on labelled-only brackets gives p0 for every row (cross-fitted for labelled rows; see validation).
2. Build soft timelines: observation weight w = p(row true) for unlabelled, 1/0 for labelled (gold true = 1; gold false rows contribute a NEGATIVE observation: "value v is not true at date t", useful for stale-value detection).
3. New features: weighted support for claimed value within +-d days (d in 7/30/90), weighted support for the best competing value in the same window, weighted before/after brackets built from soft observations (use the nearest observation with w>0.8, plus the weighted mass), number of distinct documents. Keep these separate from labelled-bracket features so the GBM learns the reliability of each.
4. Retrain on labelled rows with these features, re-predict unlabelled, iterate 2-3 rounds with damping (p_new = 0.5 p_old + 0.5 p_new) to prevent runaway.
5. Cap confirmation loops: exclude the row itself and rows from the same document (if doc id inferable from text/date adjacency) when computing its features.
Validation (honest): Date-grouped CV on labelled rows, but in each fold mask fold labels everywhere (including in the soft-observation pool; treat held-out rows as unlabelled, exactly like test), and never tune the iteration count/damping on the fold being scored (nested or fixed in advance). To mimic test density, subsample: labelled pool = 1.5k labels, unlabelled pool = the rest of practice only gives 10% density; you cannot fully reproduce the 10x universe, so ALSO check on a synthetic proxy: build timelines from practice gold facts + gold-fact pseudo-rows, thin out labels. Report both and trust the smaller gain.
Pitfalls: (1) correlated lies: a false page may repeat the same invented value in many rows (copy/echo), and truth-discovery methods fail when liars are the majority for an item (Dong et al. copy detection); weight by distinct-date/distinct-document support, not raw count. (2) Hype: lies may be systematically inflated numbers repeating across decks; don't let repetition alone validate. (3) Prior leakage: labelled false rows were presumably produced by a generator; an unlabelled false row's value is "invented" and usually appears once, so "singleton value, no corroboration" is itself a feature, but test the feature on practice only if the practice is sampled like the test. (4) Do not train the GBM on its own pseudo-labels (self-training on the judge's labels without cross-fitting yields overconfident, uncalibrated outputs; ll worsens even if acc rises).

## Rank 3: Per-fact probabilistic timeline model (sticky HMM / hazard + monotone constraints) as extra features
What: For each (subject, attribute) fit a piecewise-constant latent-state model over time: hidden value v_t, change with hazard lambda (per attribute or global), each observation reports v_t correctly with prob 1-eps (eps from false rate ~ 0.15 for rows, lower for labelled-true), otherwise a stale or invented value. Forward-backward (exact, small state space = distinct observed values + "other") gives P(v_t = claimed value | all observations), including both sides of the date. Emit that posterior, the posterior of "claim = stale value", "claim = unseen value", and the expected time since last change.
Primary sources: Dong/Berti-Equille/Srivastava 2009 (HMM for value lifespan and "freshness" of sources, VLDB); Pal et al. 2012; Adams & MacKay, "Bayesian Online Changepoint Detection", 2007 (arXiv:0710.3742); Rabiner 1989 HMM tutorial; Kalman/state-space for numeric (Durbin & Koopman). Temporal consistency / allen intervals: Allen 1983 CACM (not needed beyond intervals-vs-points).
Why it fits: the "one side known and differs" bucket is exactly an unobserved-change-point question: claim = value before date; did it change between last observation and the row date? P(change in gap) = 1 - exp(-lambda * gap_days). Your GBM can only approximate this from raw gap features; an explicit hazard per attribute class (headcount changes often, founding date never) generalises with 252 changing facts of 502. Two-sided brackets (before=after, claim differs) are already 97% false, so the gain is confined to the asymmetric buckets.
Needs: observation lists per fact (already built), a few parameters (lambda per attribute-type, eps) fit by maximum likelihood on labelled data or via EM; CPU trivial.
Runtime: seconds.
Expected gain: +0.5 to +1.5 acc, ll -0.01 to -0.03 (est.). Honest: the GBM already sees nearest-before/after plus gaps; the HMM mostly gives a cleaner, better-calibrated single feature and handles >2 observations jointly. A full BOCPD or per-fact state-space model would NOT beat it; with <5 observations per fact the likelihood is dominated by the prior.
Recipe:
1. Hazard table: for each attribute, estimate from consecutive true observations of the same fact: change rate = (#pairs with different values) / (sum of gaps). Shrink toward the global rate (empirical Bayes, Gamma prior).
2. Direction priors: for each attribute, fraction of true transitions that are increases. If >=90% (headcount, customers, price list?, funding total, version), flag monotone. Then constraint features: claim < max true value observed before date (violates monotone) ; claim > min true value observed after date; claim inside [v_before, v_after] ("interpolation-plausible"). These three features likely resolve a good part of the numeric uncertain bucket deterministically. Versions: compare semantically (parse as tuple).
3. Hype/inflation features: relative deviation r = (claim - interpolated truth)/truth with sign; empirical density of r among false vs true on practice (hype lies tend toward round, inflated numbers; check digit roundness, ratio buckets like x1.1-x1.5, x2, x10). GBM takes r, log|r|, roundness of claim vs roundness of truth.
4. Stale vs invented: flags: claim equals some value true at another date (stale); date distance to the interval when that value was true (days after it ended = stale-past; days before it started = "future-dated / pre-announcement"); never-seen but within the observed value range (plausible invented) vs outside. 202 stale vs 158 invented false facts means this split is worth encoding; the stale-past with large lag is almost surely false when brackets are tight; pre-announcement is where true marketing statements ("will be X") live, check row wording (future tense, "plans", "will").
5. Output posterior as 3-4 features into the existing GBM; keep GBM+Platt final.
Pitfalls: leakage of the row's own label when estimating hazards from the same fold (estimate hazards inside the training fold only); bidirectional smoothing uses future observations, which is allowed here (the universe is a fixed snapshot) but double-check the problem statement: truth is defined by the sentence on its own date, not the publication date of evidence. Unlabelled-universe observations may carry later dates: fine. Rows whose text states its own date (as of, in Q3, since March) require using THAT date for lookup, not the row date; parse "as of" dates and compare with row date as a feature.

## Rank 4: Calibration, row-level aggregation, and abstention (mostly free ll gains)
What: (a) noisy-AND over facts in a row, (b) stacking/cross-fitting, (c) calibrated blend of gold-form-trained and parser-trained judges, (d) isotonic or Dirichlet/beta calibration per evidence bucket, (e) "unsure" as abstention.
Primary sources: Platt 1999; Zadrozny & Elkan 2002 (isotonic); Kull, Silva Filho, Flach, "Beta calibration", AISTATS 2017; Guo et al., "On calibration of modern neural networks", ICML 2017 (temperature scaling); Wolpert 1992 (stacking); Ratner et al. Snorkel for combining weak rules with learned accuracies.
Why it fits: scoring is confidence-weighted and unpublished; assume a proper-scoring-like or weighted-accuracy rule; under either, calibrated probabilities with confidence = max(p, 1-p) are the safe choice. A row is false if ANY fact is false: p_true(row) = prod_i p_i^a with exponent a fit on CV to absorb dependence and parser misses.
Expected gain: ll -0.02 to -0.05 (est.), acc +0 to +0.5. Cheap, do it last but do it.
Recipe: 1) calibrate the final score with bucket-aware isotonic (bucket = evidence type) on out-of-fold predictions only; 2) for unparsed rows use a text-only prior (85% true; ~0.85 confidence; do not output 0.5); 3) "unsure" (2% of rows): predict only when there is zero corroborating observation anywhere in the universe (labelled or unlabelled) for the subject-attribute AND the parse is confident; check precision on practice's unsure rows before enabling (if precision < ~50% abstention costs more than it saves under any plausible formula). If the formula penalises wrong 'true/false' more than 'unsure', ceiling is small (2% of rows).
Pitfalls: calibrating on in-fold predictions; calibrating the gold-fact judge and applying it to parser-fact inputs (domain shift: train and calibrate on parser output, since that's what runs on test; use gold only as an upper-bound diagnostic). Report ll on parser facts, not gold.

## What would NOT help (be skeptical)
- TruthFinder / pure iterative source-trust (Yin 2008): needs many sources asserting the same item; here each row is a single assertion and no source ID. Its "implication" between similar values is subsumed by your compat matching. Only the idea of iterating belief to fixpoint is useful (Rank 2).
- Dawid-Skene / GLAD / Bayesian classifier combination: needs annotator ids and multiple labels per item. Only usable if you can cluster rows into "sources" (doc type / author / template) and then it reduces to per-doc-type reliability priors; test whether doc-type is inferable first; otherwise skip.
- Temporal KG embeddings and TemporalFC-style fact checking (TNTComplEx, HyTE, TA-DistMult; Hernandez et al., TemporalFC, ISWC 2023): need 100k+ triples and are for link prediction; with 62 subjects, 514 pairs, 502 gold facts they will not beat explicit bracketing, and training is not 10-hour-friendly. Their only useful idea (temporal ordering and smoothness) is Rank 3.
- Allen interval algebra: observations are point events, not intervals; reduces to before/after, which you already do. Bi-temporal (valid time vs transaction time) modelling: relevant only if pages report "as of" dates different from their publish date (see Rank 3 pitfall).
- Full BOCPD or per-fact Kalman filters: data too sparse per fact.
- Label propagation / kNN on text similarity: you already measured no gain (kNN, text cues); do not revisit. Text-only classifiers beyond tense/hype cues likewise.
- Deep/LLM-based at runtime: forbidden. LLM at dev time is allowed: use it to generate paraphrase/negative training material for the attribute classifier (Rank 1), and for synthetic false rows with stale/invented/inflated patterns to augment the 114-sized uncertain bucket. Check the generated lies match the gold distribution (stale 202 vs invented 158) before training on them.

## Suggested 10-hour order
1. (2 h) Rank 1 feature route, measured vs gold ceiling. 2. (2 h) Rank 3 features (hazard, monotone interval, stale/invented/pre-announcement flags, inflation ratio), these also help rank 1's hypothesis scoring. 3. (3 h) Rank 2: soft-observation pass with cross-fitting; evaluate with the fold-masking protocol and thin-density proxy; ship only if gain > 1 point AND ll better. 4. (1 h) Rank 4 calibration on parser-fact out-of-fold output; abstention check. 5. (2 h) buffer: Docker 30-min / 6 GiB timing, determinism.

## Honest validation checklist
- Date-grouped folds; labels of the fold masked in EVERY component (timelines, hazards, pseudo-labels, calibrators).
- Evaluate on parser facts (production path), report gold-fact result only as ceiling.
- Compare against the baseline default (85% true) by bucket; show per-bucket acc/ll (no-observation, one-side, both-sides, parse-miss).
- Watch the practice-vs-test shift: practice is ~10% of the universe; features based on density (counts, nearest-observation gaps) will shift at test time. Prefer features that are relative (nearest gap in days, support ratio) over absolute counts, and recompute from the full universe at inference with the same code path used in CV (simulate by thinning).
- Fix random seeds; whole-universe passes should take < 5 min of the 30-minute budget.
